Live data recipes

Example scripts for BarDeck’s Live data button

These are examples, not part of BarDeck, and they are not supported. A Live data button runs a script on your Mac automatically, so read a script before you use it. These only use tools every Mac already has (zsh, curl and osascript) and only talk to the service named under each one. Services change without notice, so a recipe can stop working. If one does, the fix is to edit the script; no BarDeck update is needed.

The recipes

Weather

Temperature, conditions, wind and a chart of today’s temperature. Uses the free, key-less Open-Meteo service. Change the place and its latitude and longitude at the top of the script.

Is my site up?

TV now and next (UK)

What is on a channel now, how many minutes are left, and what is next. It reads Sky’s public listings feed, which is unofficial and can change or stop at any time. The listings are Sky’s, for personal use. A list of channel numbers is included.

Electricity: Bright / Glow smart meter

Live electricity use, today’s cost and a chart of today’s half-hours. It signs in to the same web service the Bright app uses, with your own Bright login, which you keep in your Mac’s Keychain rather than in any file. That service is not a published API for outsiders and can change or stop at any time.

Set one up (about two minutes)

You need BarDeck 1.4 or later. Each zip has a folder with the script, a ready-made button and a short instruction file.

  1. Make a folder called BarDeckRecipes in your home folder and copy the recipe’s .sh file into it.
  2. Open the .sh file in TextEdit and change the settings at the top (place, address, channel).
  3. In Terminal, make it runnable once. Use the script’s own name: 
    chmod +x ~/BarDeckRecipes/weather.sh
  4. Check it works. You should see a line of JSON: 
    ~/BarDeckRecipes/weather.sh
  5. In BarDeck, open the menu, choose Import layout…, pick the recipe’s button.json and choose Add to my layout.
  6. The new button says Tap to allow. Tap it, read the command it shows, and choose Allow.

Or skip steps 5 and 6: right-click the bar, choose Add button…, set the action to Live data, type ~/BarDeckRecipes/weather.sh in the command box, press Test, then Add.

Make your own

Anything that prints text can be a button: a build status, a server check, a number from a spreadsheet, a count from your inbox. The simplest recipe to start from is Is my site up?. A script prints JSON with any of these, all optional:

{"label":"Electricity","value":"412 W",
 "detail":"£0.31/kWh · today £2.18",
 "color":"orange","spark":[1,2,3,2,4],
 "url":"https://example.com"}
  • label is the small text on top, value the big text and detail the small line.
  • color is one of cyan, orange, green, purple, red, yellow or white.
  • spark is up to 60 numbers for the little chart, and url is an address a tap can open.
  • If it is not JSON, the first line becomes the value and the second the detail.

Output over 4 KB is cut off, and a script that takes more than 15 seconds is stopped. If a script fails, the button keeps its last value, dimmed and marked “stale”. BarDeck only runs a button while the bar is showing and your Mac is awake.

Why you are asked to allow it

Because a Live data button runs by itself, a layout you import can never start running anything until you have looked at it and chosen Allow. Importing a layout clears every approval, and Share layout can remove the commands before you pass a layout on.
